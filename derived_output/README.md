# Derived output

Small tables committed so the figures and reported numbers are available without
rerunning the full pipeline (which needs the CHESS-SCAPE forcing and a multi-hour
HBV run over all 16 scenarios).

|------|-------------|---------|

| `borehole_corroboration_clean.csv` | observation-forced corroboration analysis (see below) | `figures/fig04_corroboration.py` |

| File | Produced by | Backs |

| `recession_timescales.{png,pdf}` | `recession_timescales.py` | that script's own diagnostic plot; Figure S1 itself is rendered separately by `figures/figS1_timescales.py` |

Two count columns appear in `coherence_attribution_before_after.csv` and they
are not interchangeable: `n` is every candidate transition in the population,
while `n_attributed` excludes those attributed to neither store
(`rate_limiting_store == "none"`) and is the denominator behind `uz_share` and
`lz_share`. For slow FTD candidates these are 222,890 and 220,821 respectively;
the manuscript quotes the latter alongside the 79.2% unfiltered lower-zone
share, so pairing that share with `n` will not reproduce it.

The three corroboration tables are provided as derived data rather than as a
standalone script: they summarise the observation-forced HBV run and the three
borehole tests described in the paper's observational-corroboration methods.

`slow_full_flow.parquet` and the per-scenario HBV output CSVs are too large to
commit and are regenerated by the pipeline. The `.gitignore` entries for
`projection_flow.parquet` and `forcing_deltas_<rcp>.csv` are anchored to the
repository root, so the working-directory copies stay untracked while the small
copies here are committed deliberately: Figure 5 therefore renders from a fresh
clone, given the paths in the table above. Only Figures 2 and 3 need
`slow_full_flow.parquet` regenerated first.
